# 0.4 发布前修复验收（2026-09-07）

## 范围

在 `0.4` 开发线上检查鉴权、插件边界、离线阅读、文章状态和升级生命周期。
本记录不是正式 release，不修改版本号、不创建 tag，也不合并到 `main`。

## 已修复

- 插件桥接请求限定在所属插件 API 路径内，拒绝编码穿越及未知方法。所有插件静态资源施加响应级 sandbox，停用插件的资源不可访问且不缓存。
- 升级 Fastify 和 fast-uri 的锁定版本，修复依赖审计告警。
- 离线操作采用 IndexedDB 原子事务和递增顺序；进度压缩尊重显式未读操作及已发出的幂等请求，服务器旧响应不覆盖新意图。
- 刷新快照、清空缓存、关闭离线与退出登录之间使用缓存代次隔离，阻止迟到写入恢复旧数据；分页不因前页状态变化漏文。
- 首次设置保留离线账户上下文。跨标签撤销和迟到认证响应不会重新激活已退出的本地资料；过期认证允许同账户重登并保留待同步操作。
- 支持 Service Worker 但没有活动注册时，不再无限等待 `ready`；清理的 worker 查询及确认共用有限等待时间。
- 修复自动缓存刷新定时器标记与迟到滚动曝光响应覆盖收藏、喜欢、稍后读的问题。
- PWA v14 先缓存完整构建资源，再发布应用壳；覆盖未访问过的懒加载设置页面。资源错误或超时保留旧壳，不将 HTML 错当脚本缓存。
- 离线图片消息校验持久化授权、代次及撤销状态；先授权再绑定客户端，清理确认前排空缓存写入，防止旧标签页及 worker 重启后恢复旧缓存。
- 派生数据升级由单一进程持有数据库所有权。HTTP 状态读取不启动重建，失败后重试能恢复后台调度；独立 HTTP 与 Docker 单进程模式也能执行必要升级。
- 升级契约按推荐算法及特征 schema 判定，不因版本显示值、信息茧房参数或普通 Provider 切换重复重建。
- 必要升级遍历全部符合条件的文章，区分未交互文章的推荐评分与已交互文章的基础评分，完成后清除过期推荐上下文。只复用已存向量，不调用 embedding provider。
- 长时间核心迁移不再因 worker 的固定等待上限被整个容器中断；关闭容器时正确终止仍存活的子进程。

## 验证

- `npm test`：575 项通过，包括真实 Chromium IndexedDB 事务测试及 37 项 Service Worker 回归。
- `npm run typecheck`、`npm run build`、`git diff --check`：通过。
- `npm audit --omit=dev --audit-level=high --registry=https://registry.npmjs.org`：0 个漏洞。
- `node --import tsx scripts/smoke/historical-upgrade.ts`：新库及全部 8 个历史公开 tag 的迁移验证通过，已发布迁移未被改写，向量字节不变、无待迁移项、外键检查通过、重复执行幂等。
- `npx playwright test`：28 项桌面及移动端端到端测试全部通过，包含断网提示、离线冷启动、正文阅读、设置懒加载、跨标签撤销及过期会话恢复。
- 最终 Docker 镜像验收在部署前继续执行；未通过前不切换群晖实例。

## 部署边界

本次首次写入新升级契约时，已有实例需要一次阻塞式派生数据升级。升级页面展示阶段及进度，完成后恢复正常使用；不重新生成 embedding。
群晖仅加载本地构建的 `linux/amd64` 镜像。切换前停止旧容器、检查点并备份数据库，保留旧容器；验证失败时恢复旧数据库和容器。
保留 `18080` 与 `127.0.0.1:1118` 的映射，以及既有数据挂载和环境设置。

浏览器回归不能替代所有真实 iOS/Android PWA 设备测试。已缓存旧 worker 的设备需要联网获取新版本后再验证离线功能。
