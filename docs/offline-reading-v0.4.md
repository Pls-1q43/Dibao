# 邸报 Dibao 离线阅读开发规格 v0.4

## 文档状态

- 状态：产品规则已确认，可进入技术设计与实现。
- 目标版本：`0.4`。
- 适用端：普通网页和安装后的 PWA。
- 核心原则：离线是现有阅读器的数据源状态，不是独立页面或新的导航入口。

本文定义离线文章的产品行为、缓存模型、同步规则、建议接口和验收标准。实现可以在不改变用户可见行为的前提下调整内部模块划分，但不得改变本文列出的已确认规则。

## 目标

用户曾经在当前设备成功登录并完成过离线缓存后，即使完全无法连接邸报服务器，也应能够：

- 打开完整的网页或 PWA 应用壳。
- 自动进入现有推荐阅读界面并看到缓存文章。
- 按服务器生成快照时的推荐顺序阅读文章。
- 打开缓存正文，并继续使用现有阅读器框架和阅读设置。
- 执行收藏、喜欢、稍后读、已读、阅读进度、隐藏和不感兴趣等操作。
- 恢复联网后自动同步离线操作，再安全更新离线文章快照。

离线能力应是在线阅读体验的自然降级，不要求用户提前进入专用页面，也不增加“离线文章”导航项。

## 已确认的产品决策

### 功能开关

- 现有设置页提供客户端级“离线阅读”主开关，默认关闭；浏览器与已安装 PWA 各自保存，不跨客户端同步。
- 关闭后停止准备新的离线副本，也不再将网络故障回退到本地离线数据源。
- 关闭时清理当前设备的离线文章、图片、快照和离线操作，以实际释放存储空间。
- 关闭不影响服务器上的已读、收藏、喜欢或稍后读状态。
- 如果存在待同步或同步失败的离线操作，关闭前必须明确提示这些操作将丢失并要求确认。
- 主开关允许在离线时关闭。重新开启后，有网络且会话有效时自动重建离线缓存。
- 已有设备明确存储的开关值在升级后保持不变；本地缺少开关值时视为“已关闭”。

### 自动离线队列

- 自动离线队列来自服务器已经排好序的未读推荐文章。
- 默认目标数量为 `200` 篇。
- 用户可在设置中通过滑块调整，最低 `50` 篇，最高 `1000` 篇。
- 建议滑块步长为 `50` 篇，并在滑块旁始终显示当前精确数量。
- 滑块达到 `1000` 时显示“可能占用较多存储空间”的提示。
- 设置是客户端级设置，只存放在当前浏览器或已安装 PWA，不在不同客户端间同步。
- 设置值是目标上限，不是浏览器存储不足时仍必须达到的保证值。

### 稍后读和最近阅读

- 最多为 `200` 篇稍后读文章保留离线副本。
- `200` 只限制离线副本，不限制服务器上的稍后读文章总数。
- 超过上限时，优先保留最近加入稍后读的 200 篇。
- 被清理离线副本的文章仍保持稍后读状态，联网时仍正常显示。
- 当稍后读总量重新降到可缓存范围时，下次联网同步应自动补齐符合条件的旧文章。
- 最近阅读保留最近 `20` 篇离线副本。
- 当前正在阅读的文章在联网加载成功后应立即成为离线候选。

### 正文与图片

- 标题、来源、时间、文章状态和可渲染正文文字必须完成缓存，文章才计入“可离线”数量。
- 文章图片尽力缓存；图片失败不得导致正文缓存失败。
- 离线时未缓存图片使用低干扰占位，不反复显示网络错误。
- 存储空间不足时优先清理图片，再清理文章正文。

### 界面和入口

- 不增加独立的离线文章页面、路由或导航入口。
- 复用现有文章列表、筛选器、文章行和阅读器。
- 运行时只切换数据源：在线服务器或本地离线快照。
- 离线状态复用现有推荐状态灯表达，不使用长期占据页面的横幅。
- 从在线切入离线时可以短暂提示一次，后续由状态灯持续表达。

## 范围

### v0.4 必须支持

- 应用壳和阅读器框架离线启动。
- 已认证设备上的离线启动授权。
- 自动离线推荐队列。
- 稍后读和最近阅读的离线副本。
- 缓存集合内的推荐、稍后读、收藏、最新和订阅源筛选。
- 缓存正文阅读和图片尽力加载。
- 离线文章动作队列及恢复联网后的自动同步。
- 缓存数量设置、实际缓存状态、空间提示和清理能力。
- 设备级离线阅读主开关及关闭后的本地数据清理。
- 网页与 PWA 的一致行为。

### v0.4 不支持

- 独立的离线导航入口。
- 离线全文搜索。
- 离线相关文章或“你可能还喜欢”计算。
- 离线刷新订阅源。
- 离线打开原文网站。
- 在浏览器中重新运行推荐排序、向量搜索、Embedding 或 Reranker。
- 保证 PWA 完全关闭后仍能按固定时间后台更新。浏览器可能不提供可靠的周期后台执行能力。
- 跨设备同步离线缓存数量设置或已下载文件。

## 概念模型

### 离线是数据源状态

页面类型和数据源类型必须解耦：

```ts
type ReaderDataSource =
  | { type: "remote" }
  | { type: "offline"; snapshotId: string };
```

进入离线模式不应创建 `/offline` 路由，也不应改变用户当前的阅读视图概念。推荐视图仍然是推荐视图，只是其内容来自本地快照。

### 快照顺序

推荐顺序由服务器在快照生成时确定。客户端必须保存有序文章 ID 或明确的 `position`，离线时不得根据本地状态重新计算推荐分数。

离线行为可以改变行内状态，但不得重新排列当前正在使用的队列：

- 已读、收藏、喜欢和稍后读保留原位置。
- 隐藏和不感兴趣可以立即从当前列表移除。
- 新的排序只在新快照完整提交后生效。

## 用户流程

### 联网启动

1. 正常验证登录状态。
2. 立即展示在线内容，不等待离线缓存刷新。
3. 如果存在待同步操作，先同步离线操作。
4. 获取新的离线清单并增量下载缺失或变化的正文。
5. 新快照完整可用后原子替换旧快照。

### 完全离线冷启动

1. Service Worker 返回应用壳和阅读器所需静态资源。
2. 远程会话请求出现网络不可达或超时。
3. 客户端读取当前来源对应的本地离线授权和活动快照。
4. 有可用快照时直接进入现有推荐界面。
5. 没有可用快照时仍打开现有框架，在列表区域显示简洁空状态。

不得因为远程认证请求持续失败而永久停留在加载页。

### 阅读中断网

- 当前文章已有离线正文时无感继续阅读。
- 当前文章尚未缓存时保留阅读器框架，提示该文章需要联网，并提供返回推荐列表的动作。
- 返回列表后使用活动离线快照。
- 当前页面和历史记录不应因为切换数据源而新增一条导航记录。

### 恢复联网

1. 状态灯进入“已联网，正在同步”。
2. 完成会话验证。
3. 先提交离线操作。
4. 拉取服务器权威文章状态。
5. 获取并准备新离线快照。
6. 用户正在阅读时不替换当前列表；返回列表或下一次进入列表时启用新快照。

切换回在线数据源必须基于成功的服务器请求，不能只根据 `navigator.onLine === true`。

## 离线检测

`navigator.onLine` 只能作为快速信号，不能作为唯一事实来源。

### 应进入离线数据源

- 浏览器明确报告离线；或
- 对同源邸报服务器的请求发生网络级失败；或
- 对同源服务器的请求达到离线判定超时，并且设备存在有效的本地快照。

### 不应误判为离线

- `401` 或 `403`：属于认证问题，应进入登录流程。
- 参数校验、权限或其他明确的业务错误。
- 单个非关键接口失败，例如推荐解释或相关文章失败。

服务器暂时返回 `5xx` 时可以提供缓存降级，但状态文案必须是“服务器不可用，正在使用缓存”，不得伪装成普通离线。

为避免网络抖动导致界面反复切换：

- 离线模式应在一次明确网络失败后快速可用。
- 恢复在线必须完成一次会话验证和一次核心数据请求。
- 重连期间继续展示稳定的离线列表。

## 现有视图在离线时的行为

所有视图只能查询本地缓存集合，不能暗示当前结果是完整服务器文章库。

| 现有视图 | 离线行为 | 排序 |
| --- | --- | --- |
| 推荐 | 显示自动离线推荐队列 | 严格使用快照位置 |
| 稍后读 | 显示最多 200 篇稍后读离线副本 | 使用缓存的排序字段和当前选择的排序方式 |
| 收藏 | 显示缓存集合中当前收藏的文章 | 使用缓存的排序字段和当前选择的排序方式 |
| 最新 | 显示缓存集合中的文章 | 按发布时间或发现时间倒序 |
| 订阅源 / 文件夹 | 在缓存集合内继续筛选 | 继承当前视图排序 |

离线时禁用：

- 搜索提交。
- 全文搜索。
- 相关文章。
- “你可能还喜欢”的在线加载。
- 刷新订阅源。
- 打开原文。
- 依赖在线插件接口的动作。

禁用控件应保留位置和可读标签，说明“联网后可用”，不得点击后才弹出通用网络错误。

## 推荐状态灯

复用现有推荐状态灯及其详情区域，至少支持以下状态：

| 状态 | 主文案 | 详情 |
| --- | --- | --- |
| 在线 | 推荐可用 | 沿用现有推荐状态详情 |
| 离线缓存 | 离线 · N 篇可用 | 快照时间、正文数量、待同步操作数 |
| 重连同步 | 已联网 · 正在同步 N 项操作 | 同步进度和当前仍使用的快照时间 |
| 服务器降级 | 服务器不可用 · 正在使用缓存 | 最近成功连接时间 |
| 无缓存 | 离线 · 无可用缓存 | 引导用户联网后自动准备 |
| 同步失败 | N 项操作同步失败 | 重试动作和简洁错误说明 |

状态不能只靠颜色表达。状态灯和详情需要可访问文本，并支持键盘访问。

离线详情建议显示：

- 实际可离线文章数和设置目标数，例如 `186 / 200`。
- 自动推荐、稍后读和最近阅读的逻辑数量。
- 最后成功快照时间。
- 正文和图片的估算占用空间。
- 待同步及失败操作数量。

## 设置

在现有设置中增加“离线阅读”分组，不增加新的一级页面。

### 离线阅读主开关

- 控件：开关，默认关闭。
- 关闭时：有离线副本时先确认，有待同步操作时显示更强的丢失警告。
- 关闭后：隐藏目标数量、容量和立即更新控件，显示“此设备不会保存或使用离线文章”的状态说明。
- 重新开启：保留之前设置的目标数量，联网时后台重建缓存。

### 自动离线文章数量

- 控件：滑块。
- 最小值：`50`。
- 默认值：`200`。
- 最大值：`1000`。
- 建议步长：`50`。
- 设置旁显示当前值和实际已缓存数量。
- 达到 `1000` 时显示较高空间占用提示。
- 浏览器支持存储估算时显示预计占用；不支持时不展示虚假精确数字。

调高目标：

- 保存设置后在后台补齐。
- 离线时可以保存新目标，恢复联网后执行。

调低目标：

- 从推荐快照末尾开始清理。
- 如果文章仍属于稍后读、最近阅读或当前文章，则只移除推荐成员关系，不删除正文。
- 不得中断当前阅读。

### 缓存管理

设置中还应提供：

- 实际已缓存篇数。
- 正文和图片占用空间估算。
- 最后更新时间。
- “立即更新”动作。
- “清除离线缓存”动作。

清除离线缓存是破坏性操作，应确认后执行，但不得删除服务器文章状态或稍后读状态。存在待同步操作时，必须提示清除会丢失这些操作。

## 缓存集合

一个文章正文只保存一份，可以同时拥有多个逻辑成员关系：

```ts
type OfflineMembership = {
  recommendedPosition: number | null;
  readLater: boolean;
  recentReadingPosition: number | null;
  currentArticle: boolean;
};
```

默认目标下理论逻辑上限约为：

```text
200 自动推荐 + 200 稍后读 + 20 最近阅读
```

由于集合重叠，实际唯一文章数通常小于 420。自动推荐设为 1000 时，理论唯一文章数可能达到 1220，因此必须增量同步并执行容量管理。

## 客户端存储模型

结构化文章数据、快照和操作日志应存入 IndexedDB。Service Worker 的 Cache Storage 用于应用壳、构建资源和尽力缓存的文章图片。

建议至少包含以下记录：

```ts
type OfflineSnapshotRecord = {
  id: string;
  scopeKey: string;
  generatedAt: number;
  rankContext: string | null;
  recommendedTarget: number;
  recommendedArticleIds: string[];
  readLaterArticleIds: string[];
  recentArticleIds: string[];
  status: "staging" | "active" | "superseded";
};

type OfflineArticleRecord = {
  scopeKey: string;
  articleId: string;
  detail: ArticleDetail;
  contentRevision: string;
  cachedAt: number;
  lastAccessedAt: number;
  membership: OfflineMembership;
  mediaStatus: "none" | "partial" | "complete";
};

type OfflineActionRecord = {
  clientActionId: string;
  scopeKey: string;
  articleId: string;
  sequence: number;
  createdAt: number;
  request: ArticleActionRequest;
  status: "pending" | "syncing" | "failed";
  attemptCount: number;
  lastErrorCode: string | null;
};
```

`scopeKey` 必须至少区分服务器实例和认证用户，防止同一浏览器访问不同实例或用户后串用缓存。

## Service Worker

当前 Service Worker 已能缓存应用壳，但 API 请求不进入缓存。v0.4 应保持“应用壳缓存”和“结构化文章缓存”职责分离：

- Service Worker 继续负责导航回退、HTML、JS、CSS、字体和图标。
- Service Worker 必须确保阅读器主路径所需构建资源已缓存，包括动态加载但离线阅读必需的资源。
- API 响应不直接使用不透明的 HTTP 缓存替代 IndexedDB 数据模型。
- 文章图片可以使用独立、可清理的运行时缓存。
- 新旧应用壳版本切换不得删除尚未迁移的离线文章和待同步操作。

Service Worker 更新和 IndexedDB schema 更新必须兼容。迁移失败时保留旧缓存并回退到可读状态，不得静默清空用户待同步操作。

## 建议服务端接口

为了支持最多 1000 篇文章和增量同步，不建议让客户端逐篇无条件请求详情。建议增加离线清单接口，并批量获取变化正文。

### 获取离线清单

```http
GET /api/offline/manifest?recommendedLimit=200&readLaterLimit=200&recentLimit=20
```

建议返回：

```ts
type OfflineManifestResponse = {
  snapshotId: string;
  generatedAt: string;
  rankContext: string | null;
  recommended: Array<{
    articleId: string;
    position: number;
    contentRevision: string;
  }>;
  readLater: Array<{
    articleId: string;
    addedAt: string;
    contentRevision: string;
  }>;
  recent: Array<{
    articleId: string;
    openedAt: string;
    contentRevision: string;
  }>;
};
```

约束：

- 推荐清单直接读取现有持久化排序结果。
- 该接口不得同步触发排名重算、推荐解释、Embedding、KNN、Reranker 或全文抽取。
- 推荐候选默认排除已读、隐藏和不感兴趣文章。
- 清单应包含客户端执行离线视图排序所需的状态时间字段。

### 批量获取正文

可以新增批量接口，或在客户端限制并发调用现有详情接口。优先推荐批量接口：

```http
POST /api/offline/articles/batch
```

```json
{
  "articleIds": ["article-1", "article-2"]
}
```

单批建议限制为 20 至 50 篇。响应只返回请求文章的 `ArticleDetail` 和 `contentRevision`，客户端根据 revision 只下载新增或变化正文。

如果某篇文章没有可渲染正文，客户端不得将它计入离线可用数；可以继续获取推荐清单后续候选，直到达到目标或候选耗尽。

### 幂等文章动作

现有文章动作接口需要接受客户端生成的幂等 ID：

```json
{
  "clientActionId": "device-generated-uuid",
  "type": "favorite",
  "value": true,
  "metadata": {
    "origin": "offline"
  }
}
```

服务器重复收到相同 `clientActionId` 时必须返回同一个逻辑结果，不得重复写入行为事件或重复影响推荐画像。

## 快照更新算法

1. 获取新 manifest。
2. 对比本地 `contentRevision`，计算新增、变化和可复用文章。
3. 创建 `staging` 快照。
4. 分批下载缺失正文，并写入 IndexedDB。
5. 对图片执行尽力缓存，不阻塞正文完成。
6. 验证所有准备进入可用集合的文章都有可渲染文字。
7. 在单次事务中把新快照改为 `active`，旧快照改为 `superseded`。
8. 清理不再被任何活动成员关系引用的正文和图片。

任意步骤失败时：

- 继续使用旧活动快照。
- 保留已下载且 revision 有效的正文，供下次增量复用。
- 不得激活半成品快照。

## 离线动作与冲突处理

### 基本原则

- 本地先成立：离线操作立即更新列表和阅读器。
- 显式意图优先：恢复联网后重放用户明确操作。
- 阅读进度合并：不同设备的阅读进度取最大值。
- 无冲突弹窗：正常多设备冲突不要求用户手工选择。
- 先同步动作，再刷新快照。

### 操作压缩规则

提交前可以在不改变用户最终意图的前提下压缩操作：

| 动作 | 合并规则 |
| --- | --- |
| 收藏、喜欢、稍后读 | 同文章、同字段保留最后一次明确值 |
| 标记已读 / 未读 | 保留最后一次明确值 |
| 阅读进度 | 保留最大进度；明确标为未读时按服务端既有状态契约处理 |
| 打开文章 | 同一文章只需提交一次未确认的 open |
| 隐藏、不感兴趣 | 保留明确操作，离线界面立即移除 |
| impression | 离线模式不生成 |

自动阅读进度和显式动作需要保持必要的先后语义。不得为了压缩而让“先收藏后取消收藏”的最终状态变成收藏。

### 恢复联网后的顺序

1. 验证会话。
2. 获取同步锁，确保同一浏览器只有一个标签页执行提交。
3. 按本地 sequence 分批提交待同步操作。
4. 用服务器响应 state 更新本地文章状态。
5. 获取仍受影响文章的权威状态。
6. 所有可提交操作完成后再刷新离线 manifest。

网页多标签和 PWA 同时打开时，可以使用 BroadcastChannel 或等价机制共享同步结果，并使用 IndexedDB 锁或租约选出唯一同步执行者。

### 错误处理

- 登录过期：暂停同步并保留队列，重新登录后继续。
- 临时网络错误：指数退避后重试。
- 重复提交：由 `clientActionId` 幂等处理。
- 文章已删除：丢弃对应操作并清理本地副本。
- 永久校验失败：标记失败，状态灯显示失败数量并提供重试。
- 单个操作失败不得阻塞其他无依赖操作，也不得阻塞离线阅读。

## 本地列表状态

离线动作对当前列表的影响与在线列表稳定性规则一致：

- 收藏、喜欢、稍后读、打开、阅读进度和已读只更新行内状态。
- 隐藏和不感兴趣立即从当前列表移除。
- 未读筛选不得在用户点击文章或被动状态变化后突然让当前行从指针下消失；重新进入视图时再应用严格筛选。
- 离线滚动不发送 impression，也不将文章变成 ignored。

## 认证与数据隔离

### 离线启动资格

只有满足以下条件的设备才能离线进入缓存阅读：

- 当前来源曾经成功完成认证；
- 存在与该来源和用户匹配的活动快照；
- 用户已经在当前设备上明确开启离线阅读；
- 用户没有在该设备上明确退出登录或清除离线数据。

远程会话在离线期间自然过期，不应使已下载文章突然不可读。恢复联网后必须重新认证才能提交操作和更新缓存。

### 退出登录

- 明确退出登录后清除该 scope 的离线文章、图片、活动快照和本地离线授权。
- 存在待同步操作时必须警告用户退出会丢失这些操作。
- 清除一个 scope 不得影响同一浏览器中的其他服务器实例或用户缓存。

浏览器用户配置文件是 v0.4 的本地信任边界。v0.4 不额外提供离线 PIN 或本地内容加密界面。

## 存储和清理

### 持久化与估算

- 在浏览器支持时请求 persistent storage。
- 使用存储估算 API 展示近似占用，不承诺精确字节数。
- 浏览器拒绝持久化时仍可工作，但状态详情应说明离线内容可能被系统清理。

### 清理优先级

发生容量压力时按以下顺序处理：

1. 清理不可达、失败或已过期的图片缓存。
2. 清理最近阅读集合中最旧且不属于其他集合的文章。
3. 从自动推荐队列末尾开始清理。
4. 清理超过 200 上限的稍后读离线副本。
5. 必要时清理未超过上限但最旧的稍后读图片，再考虑正文。

始终保护：

- 当前正在阅读的正文。
- 尚有待同步操作的文章状态记录。
- 活动快照提交所必需的数据。

当浏览器无法满足目标数量时，设置和状态灯显示实际值，例如 `可离线 742 / 1000 篇`，不得将其当作整体同步失败。

## 性能约束

- 在线首屏和打开文章不得等待离线缓存刷新。
- 缓存刷新必须在用户可见请求之后后台执行，并限制并发。
- 正文批量写入不得长时间阻塞主线程。
- 图片下载并发应低于正文下载，并可在页面进入后台时暂停。
- 离线快照接口只读取已有文章、状态和持久化排序，不触发任何昂贵推荐计算。
- 应记录 manifest、正文批次和图片阶段的耗时，但不得记录正文内容或私密 URL 参数。

## 可观测状态

建议记录以下本地诊断，不作为推荐信号：

- 当前活动 snapshot ID 和生成时间。
- 目标数量和实际可用数量。
- 正文、图片和失败文章数量。
- 待同步、同步中和失败操作数量。
- 最近一次同步开始、完成和失败时间。
- 最近一次离线切换原因：浏览器离线、网络失败、超时或服务器降级。

不得因为离线列表展示或滚动生成 impression。离线缓存行为本身也不得作为正向或负向兴趣信号。

## 建议实现阶段

### 阶段一：离线启动和只读快照

- 扩展 Service Worker，保证完整阅读器应用壳可离线启动。
- 建立 IndexedDB schema、scope 和活动快照。
- 增加 manifest 和批量正文接口。
- 实现推荐列表和正文的只读离线回退。
- 接入推荐状态灯。

### 阶段二：设置和完整缓存集合

- 增加 50 至 1000 的设备级设置。
- 增加稍后读 200、最近阅读 20 和集合去重。
- 实现收藏、最新和订阅源的本地筛选与排序。
- 增加空间估算、立即更新和清除缓存。
- 增加图片尽力缓存和占位。

### 阶段三：离线动作同步

- 增加操作日志和乐观状态。
- 扩展服务端 `clientActionId` 幂等能力。
- 实现操作压缩、同步锁、重试和错误状态。
- 实现恢复联网后“动作 -> 状态 -> 快照”的顺序。

### 阶段四：稳定性与容量测试

- 多标签竞争和崩溃恢复。
- 1000 篇文章的增量更新与容量压力。
- Service Worker 和 IndexedDB schema 升级。
- 网页、桌面 PWA 和移动 PWA 的离线冷启动。

## 验收标准

### 应用壳

- 至少成功在线打开一次后，断网刷新普通网页可以进入阅读器框架。
- 安装后的 PWA 在完全断网时可以冷启动。
- 离线启动不会永久停留在会话加载页。
- 阅读器所需 JS、CSS、字体和图标均可用，无空白页。

### 排序与内容

- 离线推荐文章顺序与生成快照时的服务器顺序一致。
- 离线状态变化不会重排当前队列。
- 每篇计入可用数量的文章都能打开并显示文字正文。
- 图片失败时正文仍可正常阅读。
- 新快照下载中断后仍继续使用旧快照。

### 设置与容量

- 离线阅读主开关默认关闭；已有设备保留明确存储的开关值，本地缺少开关值时保持关闭。
- 关闭后不再更新或使用离线副本，本地文章、图片、快照和操作队列被清理。
- 关闭不修改服务器文章状态；存在待同步操作时必须二次确认。
- 重新开启并联网后自动准备新快照，且保留上次的目标数量。
- 默认目标为 200，最低不能小于 50，最高不能超过 1000。
- 设置为 1000 时出现较高空间占用提示。
- 调低目标后从推荐队列末尾清理，不删除仍属于稍后读或最近阅读的正文。
- 稍后读服务器列表可以超过 200，但离线副本不超过 200。
- 状态灯和设置页显示实际数量而不是只显示目标数量。

### 视图和状态

- 不出现新的离线一级入口或离线路由。
- 推荐、稍后读、收藏、最新和订阅源筛选复用现有界面。
- 非推荐视图明确说明仅显示缓存集合。
- 状态灯能够区分在线、离线、重连、无缓存和同步失败。
- 离线搜索、相关文章、刷新和打开原文在操作前即显示不可用。

### 动作与同步

- 离线收藏、喜欢、稍后读、已读和阅读进度立即更新本地状态。
- 恢复网络后先同步动作，再更新离线快照。
- 重复提交同一 `clientActionId` 不产生重复行为事件。
- 阅读进度不会因其他设备或旧服务器状态而倒退。
- 离线滚动不生成 impression。
- 登录过期或临时网络失败不会丢失待同步操作。

### 清理与安全

- 同一文章属于多个集合时只保存一份正文。
- 空间不足时优先清理图片和低优先级文章。
- 当前阅读文章和待同步操作不会被自动清理。
- 明确退出登录会清理当前 scope 的离线数据。
- 不同来源或用户的缓存不会互相显示。

## 测试矩阵

至少覆盖：

- Chrome / Edge 普通网页。
- Chrome / Edge 桌面 PWA。
- Android PWA。
- iOS / iPadOS 添加到主屏幕场景，在能力允许时验证。
- 缓存 50、默认 200 和最大 1000 三个规模。
- 有缓存、无缓存、缓存过期、快照更新中断和浏览器存储不足。
- 离线冷启动、阅读中断网、网络抖动、恢复联网和登录过期。
- 单标签、多标签以及网页与已安装 PWA 同时打开。
- 正文完整、仅文本、图片部分失败、文章被服务器删除。

端到端验证应确认：

- 无 Vite 或运行时错误覆盖层。
- 无未处理 Promise rejection。
- 离线列表和正文不发生明显布局跳动或文本溢出。
- 状态灯文案与真实数据源一致。
- 断网和重连不会在用户阅读过程中重排当前列表。
